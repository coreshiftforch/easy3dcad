# かんたん3D CAD

3Dプリンターで刷れるキーホルダーのデータを、**ブラウザだけ**でつくれるアプリ。
インストール不要・CADの知識不要・データは端末の外に出ない。

3つのつくるものを1つのアプリにまとめている。

| ページ | つくるもの | 出力 |
|---|---|---|
| `nameplate.html` | なまえプレート（形・フォント・色・穴を選ぶ） | 3MF（2色）・STL |
| `qr.html` | QRキーホルダー（URLを入れるとQRの立体になる） | 3MF（多色）・STL・PNG |
| `clicker.html` | クリッカーメーカー（3Dモデルをキースイッチで押せる上下2パーツにする。手もとに無ければ**その場で作れる**） | 3MF・STL |

## 動かす

```
npm install
npm run dev        # http://localhost:5173/
npm run build      # dist/ に出る（これが提出物）
npm run preview    # dist/ を確かめる
npm run check:kana # ひらがな切替の取りこぼし検査
npm run check:split # 上パーツが割れたときの切り分け検査
npm run check:colors # 色の出どころが1か所のままか検査
npm run check:make # 「モデルを作る」でできる形の検査
```

`起動.bat` をダブルクリックすれば、初回セットアップ（`npm install`）から
開発サーバー起動・ブラウザ表示までまとめてやる。

### なぜ public/ に分けているか

なまえプレートとQRキーホルダーは、**three.js を CDN の importmap で読む単一HTML**。
これを Vite にビルドさせると、npm 側の three（0.185）で解決しようとして
食いちがう。`public/` に置いたものは Vite が一切さわらないので、
書いたままの形で配られる。

いっぽう クリッカーメーカーは npm の three を `import` するモジュール構成なので、
Vite のエントリ（`clicker.html` → `/src/main.js`）として束ねている。

つまり **three.js が2系統ある**が、ページが別なので競合しない。

## ひらがな切替

ふだんは ふつうの日本語。ヘッダー右上の「⇆ あいうえお」で漢字をひらがなに開ける。
選んだ状態は `localStorage` に残るので、ページをまたいでも保たれる。

しくみは `public/js/kana.js`。**漢字→ひらがな の一方向だけ**変換する
（逆向きは読みが定まらないのでやらない）。漢字のかたまりだけ置きかえ、
送りがなは残すので `['大き','おおき']` ひとつで 大きさ／大きい／大きく をまかなえる。

> **★文言に漢字を足したら `npm run check:kana` を走らせること。**
> `kana.js` の語彙に入れ忘れると、ひらがなモードで漢字が残る。
> 検査は画面に出る文字を2か所（HTMLのタグの中／JSの文字列リテラル）から集めて、
> 開けなかった漢字を一覧で出す。
>
> 複合語で読みが変わるものは、長いかたちも一緒に入れる。
> 例) `['最','さい']` だけだと「最初」が「さい初」になる。`['最初','さいしょ']` を足す。

## つづきから再開

ページを読み直したとき、前の作業が残っていれば
**「つづきから」か「さいしょから」かを聞く**（4ページとも）。

しくみは `public/js/resume.js`。`window.Resume` を作るだけの素のスクリプトなので、
単一HTMLのページからも Vite が束ねるクリッカーからも、同じものを `<script>` で読める。

```js
const back = await Resume.check('nameplate');   // 保存があれば聞く
if (back) { …back.data で組み立てる… }
Resume.keep('nameplate', { label:'④ 大きさ', data: state });   // 変わるたび
Resume.forget('nameplate');                      // さいしょに戻すとき
```

- 保存先は `localStorage`。**読みこんだ3Dモデルの中身だけは数MBあるので
  `IndexedDB` に別で置く**（`Resume.keep` の `file` に渡す）。
  同じファイルなら書き直さない（`名前:バイト数` で見ている）
- 2週間より古い保存は使わない。`localStorage` が使えないブラウザでは黙って何もしない
- **`confirm()` は使わない。** 画面の中のダイアログで選んでもらう
- **「さいしょから」は、そのページの①ではなく トップ（3つから選ぶ画面）へ行く。**
  作り直すなら、まず何を作るかから選びたいため。
  ★消しおわってから移ること（IndexedDB の削除は非同期）
- ダイアログの色は `tokens.css` の `--c-…`。文字は kana.js の MutationObserver が
  拾うので、ひらがなモードでもそのまま開ける

### ページごとの覚えかた

| | 覚えるもの | やり方 |
|---|---|---|
| なまえプレート | `state` まるごと | JSONにできるので、そのまま覚えて `Object.assign` で戻す |
| QRキーホルダー | 操作パネルのつまみ＋読みこんだSTL | つまみを覚えて戻す（値を入れて `input` を投げる） |
| クリッカーメーカー | モデルの中身・どの作り・フローの何番＋つまみ | 同上。モデルは読みこみ直す |
| クリッカーの「モデルを作る」 | 操作パネルのつまみ | まだモデルが無いので、つまみだけ |

QRとクリッカーで `state` ではなく**つまみ**を覚えているのは、state と画面が
1対1になっていないため。`Resume.readForm(root)` / `Resume.writeForm(root, snap)` が
まとめて面倒を見る。見分けは **並び順**（idの無いつまみが多いので）。

> **★戻すときは、先にステップを移してから つまみを入れること。**
> クリッカーのフローは、そのステップに入るたびにバーの動く範囲を決め直す。
> つまみを入れてからステップを移すと、その値が上書きされる
> （②の「大きさ（半径）」が 8.1 → 9.1 に戻ってしまった）。

### 覚えないもの

- クリッカー②の「自分で描く」でなぞった線（つまみに出ないので戻せない）
- クリッカーの書き出し画面。戻すのは、その手前のフローまで
- カメラの向き・ズーム
- **いちばん最初の画面**。まだ何もしていないので、読み直しても聞かない
  （はじめの状態と見くらべて、1つでも変わっていれば覚える）

## デザイン

トップ・なまえプレート・QRキーホルダーは `public/css/common.css` の同じ骨組みに乗せている。

```html
<header>…タイトル＋メニューへ戻るリンク…</header>
<div class="main">
  <div class="stage"><canvas>…3Dプレビュー…</canvas></div>
  <div class="side">
    <div class="steps">…丸いステップ表示…</div>
    <div class="panel">…操作パネル（.step-page / .sec を1つずつ出す）…</div>
    <div class="nav">…もどる／つぎへ…</div>
  </div>
</div>
```

- **スマホ幅**: たて1列（3Dが上、操作が下）
- **900px以上**: 左に操作パネル、右に3Dビューの横ならび
  （`.main` を `row-reverse` にしているので、DOMは `stage → side` の順で書く）

### 色は1か所（`public/css/tokens.css`）

**色を変えたいときは `public/css/tokens.css` だけを直す。** 4ページぜんぶが変わる。

`common.css` は先頭で `@import` して、`style.css` は `clicker.html` の `<link>` で
読んでいる。どちらも `--c-…` を自分のところの名前に入れなおしているだけ。

```
tokens.css   --c-bg / --c-panel / --c-accent …   ← 値があるのはここだけ
  ├ common.css  --bg  --panel  --accent  …       （なまえプレート／QR／トップ）
  └ style.css   --bg  --card   --accent-fill …   （クリッカー）
```

以前は同じ値を2か所に書き写していて、「片方だけ直すと3ページで色がずれる」
という注意書きを付けていた。その注意書きごと要らなくした。

#### 知らせの色は「4段」になっている

よい／注意／だめだった の3つには、1つにつき4段ある。**名前の数字が大きいほど明るい。**

| | 使うところ | 例（よい） |
|---|---|---|
| `--c-ok-bg` | 暗い地（知らせの背） | `#052e22` |
| `--c-ok` | こい。明るい地に置くベタ塗り・ステップの丸のふち | `#047857` |
| `--c-ok2` | あかるい。暗い地に乗せるふち・小さい文字 | `#34d399` |
| `--c-ok3` | うすい。暗い地に乗せる本文 | `#a7f3d0` |

**以前は3ページとクリッカーで、同じ `--ok` という名前が別の段を指していた**
（3ページ＝こい、クリッカー＝あかるい）。だから「揃えると見た目が変わる」ことに
なっていた。段ごとに名前を分けたので、両方が同じ表からそれぞれの要る段を引ける。
**値は1か所になったが、見た目は前と変わっていない。**

> **★色の値を書いてよいのは `tokens.css` だけ。** ほかのファイルに
> `--名前: #色` と書くと、また2重持ちになる。`npm run check:colors` が
> それと「`tokens.css` に無い名前を引いている」の2つを見張る。

### クリッカーメーカーの並び

クリッカーは共通の骨組み（`.main` / `.steps` / `.nav`）には乗せていない。
ステップが6つあって名前が長く（「クリッカーの位置」「十字の穴」）丸番号に入らないのと、
「正面から」「上から」の2画面が要るので、共通の形に押しこむと窮屈になるため。

そのかわり **「操作は左・3Dは右」だけは4ページで揃えてある**。クリッカー側は
DOM が `窓 → パネル` の順なので、横に広い画面のときだけ `order` で並べかえている。

> **★`.side` という名前は、シーン1の「モデルを作る」の列と
> シーン3の窓（`.view.side` ＝正面から）でかぶっている。**
> 裸の `.side { … }` を書くと窓のほうにも当たる（`order` を裸で書いて、
> シーン3の2つの窓が左右入れかわった）。必ず `.stage > .side` と書くこと。

## モデルを作る（クリッカーの①から入る）

クリッカーは3Dモデルを読みこんで使うが、**手もとに無い人のために**
その場で作れる小さなCADを付けてある（`src/scenes/scene0-make.js`）。

板（土台）の上に、**文字**か**QR**を **のせる**か**彫る**だけ。

| | えらべるもの |
|---|---|
| 土台のかたち | 四角（角丸）・まる・たまご・六角 |
| 大きさ | よこ幅 25〜120mm ／ 厚み 6〜45mm |
| のせるもの | なし ／ 文字（書体6つ・大きさ％） ／ QR（URL・大きさ％・よごれへの強さ） |
| のせかた | 彫る ／ のせる（深さ 0.4〜3mm） |

できたものは**二進STLに書いてから `readModelFile` に通して**、シーン2へ渡す。
こうすると「読みこんだモデル」とまったく同じ形（`name` / `positions` /
`size` / `notes`）で出てくるので、**その先の手順は1行も変えなくてよい**。

### 立体の引き算（ブーリアン）は使っていない

彫るのは、**板を2枚に分ける**だけでよい。下の板は穴なし、上の板は
文字のかたちの穴あき。`ExtrudeGeometry` は `Shape` の `holes` を
そのまま抜いてくれるので、引き算の計算がいらないし、面も壊れない。

> **★穴の中の「島」を忘れないこと。** 「あ」「お」のように中が閉じている字は、
> 穴の中に残る島を別に立てないと、そこまで抜けおちる。
> `npm run check:make` は **彫った体積が「字の面積 × 深さ」ぴったりか**を見ているので、
> 島を忘れると減りすぎてすぐ分かる。

> **★穴どうしが触れると earcut がこわれる。** QRのマスは となりどうしが
> くっつくので、横につながるぶんは1つの長方形にまとめ、**上下にはマスの2%だけ
> すきまを空けて**離してある。印刷の線の太さよりずっと細いので、刷ればつながる。

### 書体に漢字が入っていない

`gothic` / `maru` / `pop` / `mincho` / `robo` は なまえプレート用の
**かな＋英数字だけ**の書体。漢字を打つと、その字は黙って消える。
そこで **打った字がその書体に無ければ名指しで知らせ**、漢字のそろった
`IPAexGothic.ttf`（「かんじ」）へ誘導している。6MBあるので、
選ばれたときにだけ読む（初回は数秒かかるので「作っています…」と出す）。

## つくる → 印刷までの流れ

1. トップでつくるものを選ぶ
2. ステップに沿って進める（3Dプレビューがその場で更新される）
3. STL または 3MF でダウンロード
4. スライサー（Bambu Studio など）で開いて印刷

3MF はパーツごとに色が分かれているので、複数フィラメントの機種ならそのまま色分けして刷れる。
STL は単色だが、どのスライサーでも開ける。

## 元になったアプリ

別々に作っていた3つのアプリを1つにまとめたもの。

- なまえプレート … `公民館イベントアプリ/cad3D_printing_ver2`
  （BASE決済・注文GAS連携は削除し、無料ダウンロードに変更）
- QRキーホルダー … `QRコード3Dアプリ`
- クリッカーメーカー … `projects/clicker-maker`
  （`フィギュアキーキャップ` の単一HTML版を作り直したもの。旧版はもう使わない）

外部サービスへの送信は一切行わない。生成したデータは端末の中だけで完結する。
