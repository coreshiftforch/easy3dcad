① 作品概要（00:00-00:20）※必須
────────────────────────────────────────────────────────────────────

【画面】タイトル → トップ画面（3つのカードが並ぶところ）

【ナレーション／テロップ】
  ZEROモデリング。
  3Dプリンターで刷れるデータを、ブラウザだけで作れるWebアプリです。
  インストールも、CADの知識も、ゼロから始められます。
  作れるものは3つ。なまえプレート、QRキーホルダー、
  そして、好きな3Dモデルを「押せるクリッカー」に変えるクリッカーメーカー。

【画面に出す文字】
  ・インストール不要／ログイン不要／通信なし
  ・スマホでもPCでも同じように動く
  ・URL  https://coreshiftforch.github.io/easy3dcad/


────────────────────────────────────────────────────────────────────
② 制作背景（00:20-00:45）
────────────────────────────────────────────────────────────────────

【画面】公民館イベントの写真（あれば）／3Dプリンターで刷ったネームプレートの実物

【話す内容（要点）】
  ・きっかけは、地域の公民館で子ども向けに開いた3Dプリンター体験。
    既存のCADソフトは小学生にはむずかしく、その場で使えるものがなかった。
  ・そこで「打った名前が立体になるだけ」のアプリを自分で作って使った。
    → 実際にイベントで使ってもらい、その反応をもとに作り直したのがこの作品。
  ・作っていくうちに「QRを立体にしたい」「フィギュアをクリッカーにしたい」と
    対象が広がり、3つのアプリになった。それを1つにまとめたのがZEROモデリング。

【画面に出す文字】
  「小学生でも使えるモデリングアプリを」（開発初日に自分で書いた目標）

★実物（刷ったネームプレート、クリッカー）を手に持って映すと強いです。

③ システム構成（00:45-01:05）
────────────────────────────────────────────────────────────────────

【画面】下の構成図をスライドで

  ┌──────────────────── ブラウザ（PC / スマホ）────────────────────┐
  │                                                                  │
  │  [入力]                [処理：すべてブラウザ内で完結]     [出力] │
  │                                                                  │
  │  文字 ─────→ opentype.js ─→ 輪郭 ─┐                            │
  │                                     │                            │
  │  URL ──────→ qrcode-generator ─→ 白黒配列 ─┤                    │
  │                                     ├→ 自作ジオメトリ演算 ──┐   │
  │  3Dモデル ─→ 自作ローダ ─→ 三角形メッシュ ┘  ・三角形分割   │   │
  │  (STL/3MF/GLB/OBJ)                            ・押し出し     │   │
  │                                               ・切り分け     │   │
  │                                               ・くり抜き     │   │
  │                                                              ↓   │
  │                                      three.js で表示 ← 立体データ│
  │                                                              ↓   │
  │                                                    STL / 3MF 書き出し
  │                                                                  │
  │  [保存] localStorage（設定・作業状態） / IndexedDB（モデル本体）  │
  └──────────────────────────────────────────────────────────────────┘
         ↑ サーバーへの送信は一切なし（データは端末から出ない）

  公開      GitHub Pages（静的ホスティング）
  自動化    GitHub Actions … pushのたびに自動検査7本 → 通れば自動公開

【話す内容】
  ・サーバーは使っていません。計算はすべてブラウザの中。
    だから、通信が不安定な会場でも動くし、子どもが作ったデータが
    どこにも送られない。
  ・three.jsは「画面に映す」ためだけに使っていて、
    形を作る計算（切る・くり抜く・彫る）は全部自分で書いています。


────────────────────────────────────────────────────────────────────
④ 作品実行の様子（01:05-02:20）※必須
────────────────────────────────────────────────────────────────────

★画面収録。テロップで技術ポイントを重ねる。3本立て（各25秒）。

【4-1】なまえプレート（25秒）
  操作   形をえらぶ → 名前を打つ → 位置を動かす → 色を2色えらぶ → できあがり
  見せ場 ・打った瞬間に立体になるところ
         ・「実物大で見る」ボタン（スマホを画面に近づけて実物と重ねる）
  テロップ「フォントの輪郭を取り出して、その場で三角形分割 → 押し出し」
         「2色プリント対応の3MFを書き出し」

【4-2】QRキーホルダー（25秒）
  操作   URLを入れる → 立体のQRになる → スマホで実際に読み取ってみせる
  見せ場 ★画面のQRを、その場でスマホのカメラで読み取るカットは必須級。
         「本当に読める」ことが一目で伝わります。
  テロップ「読み取りやすい大きさを自動で計算」
         「スライサーの修復作業が要らない3MFを出力」

【4-3】クリッカーメーカー（25秒）
  操作   ① モデルを読みこむ（または「モデルを作る」でその場で作る）
         ② 大きさと向きを決める
         ③ 溝の形を決める（「オブジェクトに沿った形」を見せる）
         ④ 十字の穴 → ⑥プレビューで分解アニメーション
  見せ場 ★プレビューの「ばらして見る」と、実物を押してカチカチ鳴らすカット。
         画面の中の分解図 → 実物のクリッカーを押す、とつなぐと効果的。
  テロップ「1つのメッシュを、水密性を保ったまま上下に切り分け」
         「Cherry MX互換スイッチの実測寸法（15.6mm角・ストローク4mm）に合わせる」

★最後に「ひらがな切替」を3秒だけ見せると、配慮の深さが伝わります
  （漢字の画面 → ボタン → ぜんぶひらがなに変わる）。


────────────────────────────────────────────────────────────────────
⑤ アピールポイント（02:20-02:50）※必須
────────────────────────────────────────────────────────────────────

【画面】箇条書きスライド（下から3つえらんで、実演カットを小さく重ねる）

  (1) CADの知識ゼロ・インストールゼロ・通信ゼロ
      URLを開くだけ。会場のWi-Fiが弱くても動く。
      子どもが作ったデータは端末から一歩も出ない。

  (2) 形をつくる計算を、ライブラリに頼らず自分で書いた
      ・任意の3Dモデルを、閉じた立体のまま上下に切り分ける
      ・複雑な形の「どこまで文字を置けるか」を、
        96×96の格子＋ヒストグラム法で内接長方形として求める
      ・内側へ寄せた輪の自己交差を、交点で切ってほどく
      CSGライブラリを使わず、三角形分割の性質を利用して彫り込みを実現。

  (3) 「刷れる」ところまで面倒を見る
      スライサーで修復を求められない3MF、2色プリント対応、
      はめあいのすきま（横0.2mm／底1.0mm）を実測で決定。
      → 画面で完成しても、刷れなければ意味がないので。

  (4) 小学生が使うことを前提にしたUI
      ・漢字→ひらがな 切替（語彙500語。押すたびに全画面が開く）
      ・実物大表示（スマホでもPCでも同じ大きさで見える）
      ・作業中に事故があっても「つづきから」再開できる
      ・スマホでは3D画面が縦の50%を占めるレイアウトに自動で変わる

  (5) 実際に使ってもらって直した
      公民館イベントで子どもに使ってもらい、
      「大きすぎた」「選びかたが分からない」を実物と反応から直した。
      3Dプリンターで実際に出力し、造形時間・寸法・はめあいを確認して
      数値を決めている。

  (6) 品質を機械で守っている
      自動検査7本（面積・体積・水密性・リンク切れ・ひらがな変換もれ・
      色の一元管理）を GitHub Actions で毎回実行し、
      通ったものだけを自動公開。

【しめの1文】
  「作りたい」と思ってから、手に取れるまでを、いちばん短くする。

      書体 6種（なまえプレートは5種、クリッカーは漢字入り6種）
      出力形式 STL・3MF・PNG
      開発期間 31日（2026/7/30～8/29）
  ・BGMは著作権フリーのものを使うか、無音＋ナレーションで。
    （提出物なので、権利のはっきりしない音源は避ける）
  ・字幕を焼きこむと、音が出せない環境でも伝わります。
