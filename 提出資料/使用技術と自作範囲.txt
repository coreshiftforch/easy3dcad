1. 技術スタック
────────────────────────────────────────────────────────────────────

言語        JavaScript（ES2022 / ES Modules）、HTML5、CSS3
            ※TypeScript・JSXは不使用。素のJSのみ。
3D描画      three.js（WebGL2）
            PerspectiveCamera と OrthographicCamera を用途で使い分け、
            レイヤー機能で1シーンを複数の窓に描き分けている
ジオメトリ  自前実装（下記2章）。CADカーネル・CSGライブラリは不使用
フォント処理 opentype.js でTTFからアウトラインを取得 →
            自前で三角形分割 → 押し出して立体化
QR生成      qrcode-generator でセル配列を計算 → 自前で立体化
ファイル入力 STL（バイナリ／ASCII）・3MF・GLB・OBJ の読み込みを自前実装
            （3MFはZIP解凍＋XML解析まで自前。DecompressionStream を使用）
ファイル出力 STL（バイナリ）・3MF（複数オブジェクト＋色情報つき）・PNG
永続化      localStorage（設定・作業状態）、IndexedDB（読み込んだモデル本体）
ビルド      Vite 8（マルチページ構成）
CI/CD       GitHub Actions → GitHub Pages に自動公開
            push のたびに7本の自動検査を走らせ、通ったものだけ公開する
バックエンド なし。サーバーへの送信は一切ない（完全クライアントサイド）

2. 自分で実装したアルゴリズム（この作品の中身）
────────────────────────────────────────────────────────────────────

(1) 文字・QRを立体に彫る／盛る
    opentype.js が返すベジェ曲線を点列に落とし、穴（「あ」の輪の中など）を
    ふくむ多角形として earcut 系の三角形分割にかけ、押し出して立体にする。
    「彫る」ときは、土台の面の多角形に対して文字を穴として与えることで、
    ブーリアン演算を使わずに1回の三角形分割で彫り込みを実現している。
    → src/geom/make.js

(2) 顔の中に入る最大長方形（内接長方形）
    ねこ・くも・リボンのような複雑な形の上に、文字やQRをどこまで置けるかを
    求める処理。形を96×96の格子で塗り、「肉の上」のマスだけでできる
    最大の長方形を、各行を柱と見たヒストグラム法（O(n)スタック法）で求める。
    文字の大きさと、位置スライダーの可動範囲の両方をこの長方形から決めるので、
    どんな形でも「オブジェクトからはみ出さない」ことが保証される。
    → src/geom/make.js（innerRect / biggestRect）

(3) 任意の3Dモデルを上下2パーツに切り分ける
    読み込んだ三角形メッシュを、指定した高さの「段のついた面」で切り分ける。
    三角形を面と交差させ、切り口の線分を集めて輪をつくり、
    その輪にふたを張って両側を閉じた立体（水密メッシュ）にする。
    切り口が2つ以上に分かれる形（ねこの耳など）にも対応している。
    → src/geom/split.js、src/geom/caps.js、検算/split-shells.mjs

(4) 溝の輪を内側へ寄せる（オフセット）と自己交差のほどき
    切り口の輪郭を、辺に垂直な向きへ一定距離ずらす（マイター接合）。
    細い部分では線どうしが交差して「8の字」になるので、交点で輪を2つに分け、
    面積の大きいほうだけを残す処理を入れている。
    → src/geom/groove.js（offsetLoop / unkink）、検算/loop-unkink.mjs

(5) 下パーツの「部屋」をくり抜く
    お椀型の下パーツに、キースイッチが入る空洞と配線の逃げをくり抜く。
    くり抜いた結果が閉じた立体のままであることを自動検査している。
    → src/geom/room.js、検算/room-through.mjs

(6) 3MFの書き出し（色つき・複数オブジェクト）
    ZIP（無圧縮ストア方式）を自前で組み立て、3D Model XMLと
    Bambu Studio/Orca Slicer が読む色設定を書き込む。
    スライサー側で「オブジェクトの修復」を要求されない、
    向き・法線のそろったメッシュを出すようにしている。
    → src/io/saveModel.js

(7) 漢字→ひらがな自動変換（アクセシビリティ）
    画面上の日本語を、漢字のかたまりだけ置きかえてひらがなに開く。
    送りがなは残すので「大き」1語で 大きさ／大きい／大きく をまかなえる。
    MutationObserver で後から出た文字も追いかける。語彙は500語。
    → public/js/kana.js、検算/kana-check.mjs

(8) 実物大表示
    画面の物理的なピクセル密度から mm→px 係数を求め、
    PCでもスマホでも「刷ったときの実物大」で見せる。

4. 品質を保つしくみ
────────────────────────────────────────────────────────────────────

・7本の自動検査を用意し、GitHub Actions で push のたびに実行。
  すべて通ったときだけ GitHub Pages へ公開される。
  ジオメトリの検査は「面積・体積が一致するか」「開いた辺が0本か」など、
  見た目ではなく数値で判定している。
・色は public/css/tokens.css の24色だけを使い、
  他のファイルに色を直接書いていないことを検査で保証（check:colors）。
・文言に漢字を足したら check:kana が「ひらがなに開けない漢字」を検出する。
